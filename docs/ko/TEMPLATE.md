| **대상** | 원본 배포 컨트랙트 fork, 테스트넷 배포, 최소 재구현 중 하나 |

*원 자료 아티팩트를 한 칸 따로 뺐다. 항목 하나만 보면 별거 아닌 칸인데, 여러 항목을 모아 놓으면 그때부터 쓸모가 생긴다.*

*`solc_version`과 `evm_version`을 `foundry.toml`에 먼저 고정하고, 표에는 거기서 옮겨 적는다. 2021년 대상 컨트랙트를 Cancun 이후 EVM에서 돌리면 EIP-6780 때문에 SELFDESTRUCT 동작이 달라진다. 엉뚱한 EVM에서 뽑은 재현은 테스트만 초록불인 오답이다.*

## 원 자료가 주장하는 것

*두세 문장을 쉬운 말로, 원 자료를 덮은 채로 쓴다. 그게 안 되면 아직 다 읽은 게 아니다.*

## 내가 한 것

*셋업과 순서. 어느 fork block을 썼고 왜 하필 그 블록인지. 도구. 단순화한 부분은 빠짐없이 적고, 하나하나 왜 결과가 달라지지 않는지 이유를 붙인다.*

```bash
forge test --match-contract <TestContract> -vvv
```

*아래 결과를 실제로 뽑아낸 명령을 그대로 붙인다. 보기 좋게 정리한 버전 말고.*

## 취약 패턴

```solidity
// 버그가 드러나는 가장 작은 조각
```

*왜 악용 가능한지 한 문단. 공격자가 결국 뭘 들고 나가는지, 그걸 내주는 동안 컨트랙트가 뭘 전제하고 있었는지를 쓴다.*

## 결과

*숫자. 전후 잔고, 트랜잭션 개수, 가스 때문에 공격이 수지가 안 맞는 경우에는 가스까지. 결과는 그 테스트가 잰 수치지 초록불 자체가 아니다.*

## 원 자료와 갈라진 지점

*이제는 성립하지 않는 전제. 발표 이후 값이 바뀐 파라미터. 원 자료가 설명한 호출 경로는 그대로인데 그 아래 컨트랙트가 조용히 업그레이드된 경우도 여기 들어간다. 분명하게 적혀 있는데 그대로 따라 해도 안 되는 단계도 마찬가지다.*

*전부 맞아떨어졌으면 맞아떨어졌다고 적는다. 그것도 결과다.*

## 검증하지 않은 것

*한계를 있는 그대로 쓴다. 무엇을 단순화했고, 무엇을 그냥 믿고 넘어갔고, 확인하려면 셋업이 어디까지 더 필요한지. 짐작으로 적은 건 결과 섹션이 아니라 여기에 적는다.*

## 메모

*미결로 남은 질문, 막다른 길, 이상해 보였는데 끝까지 쫓아가지 않은 것. 쓸데없어 보여도 이 섹션은 지우지 않는다.*

## 실행 방법

이 디렉터리는 그 자체로 완결된 Foundry 프로젝트다. 빌드하고 돌리는 데 상위 디렉터리는 필요 없다.

```bash
forge install   # 이 항목에 고정해 둔 forge-std 커밋을 받는다
forge test -vvv
```

Fork 테스트는 환경변수 `ETH_RPC_URL`을 읽는다. 블록 번호는 테스트 안에 고정해 두었으니 플래그를 따로 넘기지 않아도 된다. 오래된 블록을 잡으려면 archive node가 있어야 하는데, 그때 어떤 식으로 실패하는지는 README에 적어 두었다.
